# Contributing

Thanks for considering a contribution to the `agentic-workflow-kit` ecosystem.

This organization is early, so the best contributions are focused and specific: documentation fixes,
small improvements to repo scaffolding, issue reports with clear reproduction steps, or proposals that
make one layer easier to adopt independently.

## Before You Start

- Open an issue for substantial behavior, API, or workflow changes before sending a pull request.
- Keep pull requests narrow. One change should be easy to review and easy to revert.
- Preserve each repository's local purpose. Do not move cross-repo conventions into a repo unless that
  repo is the documented owner for the convention.
- Do not include secrets, private prompts, credentials, or unpublished customer/project data.

## Pull Request Checklist

- The change has a clear motivation.
- Documentation is updated when behavior, usage, or public project framing changes.
- Verification is included in the pull request body.
- New files use the existing license unless a repository says otherwise.
- Generated or bulky transient artifacts are excluded unless the repository explicitly tracks them.

## Review Expectations

Review is meant to protect clarity, maintainability, and independent adoption. Maintainers may ask for
scope reductions, stronger verification, or clearer docs before merging.

## Development

Each repository owns its own setup and verification commands. Read that repository's README and local
contribution notes before making code changes.
